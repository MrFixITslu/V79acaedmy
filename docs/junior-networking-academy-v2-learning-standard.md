# V79 Junior Networking Academy — Curriculum v2 Learning Standard

## Graduate outcome

A learner who completes the course should be able to **understand, trace, build, verify, document and adapt** a small network safely.

The graduate process is:

**UNDERSTAND → TRACE/TEST → BUILD → VERIFY → DOCUMENT → TRANSFER**

A polished topology is not enough. Learners should be able to explain what each component does, collect evidence, isolate a fault, make controlled changes, verify results and hand the network to another technician.

## Every lesson must provide measurable value

### Learn lessons
Every mission must include:
- a technician mental model;
- core concepts;
- technician moves;
- a worked example;
- age-appropriate Core Path and Engineer Challenge expectations;
- common failure patterns and recovery;
- safety/professional boundaries;
- teach-back explanation.

### Interactive Lab lessons
Every mission must include:
- an applied scenario;
- OBSERVE → BOUND → TEST → INTERPRET → NEXT method;
- field drills;
- transfer to a new scenario;
- evidence explanation;
- mastery evidence;
- an efficiency target.

### Build & Engineer lessons
Every mission must include:
- application to the final network;
- controlled implementation workflow;
- test evidence;
- negative/security testing where relevant;
- documentation updates;
- risk/rollback/escalation thinking;
- professional handoff;
- explicit acceptance evidence.

## Technician habits that must transfer across the course

Learners should repeatedly practice:

1. Define the exact symptom or requirement.
2. Draw or identify the relevant path.
3. Use the lowest-cost/lowest-risk useful test first.
4. State what a result proves and what it does not prove.
5. Make one controlled change at a time.
6. Test what should work.
7. Test what should remain blocked or fail safely.
8. Update diagrams, labels, addressing and change evidence.
9. Stop/escalate when a change is unsafe, unauthorized or beyond scope.
10. Explain the reasoning in their own words.

## Mission 20 — Network Technician Benchmark

The final benchmark must use an unfamiliar scenario rather than the class topology.

Each learner should complete:
- one unfamiliar troubleshooting incident;
- one design-change request;
- an evidence trail;
- verification results;
- documentation/handoff updates;
- an explanation of when they would stop or escalate.

### Graduation rubric

Score 1–4 across:

1. **SCOPE + MODEL**
2. **TEST + EVIDENCE**
3. **IMPLEMENT + SAFETY**
4. **VERIFY**
5. **DOCUMENT + HANDOFF**
6. **TRANSFER + EXPLAIN**

Recommended pass standard: **no category below 3 — Competent**.

## Red-team failure conditions

The course should be considered weakened if future edits:
- reduce Learn lessons to vocabulary lists;
- reward guessing in labs;
- teach configuration commands without explaining the network behavior;
- allow random troubleshooting changes;
- omit negative/security tests;
- treat ping as proof that every service is healthy;
- remove documentation/handoff requirements;
- remove transfer to unfamiliar problems;
- present VLANs, NAT or Wi-Fi signal strength as complete security/performance answers;
- allow the final demonstration to pass on presentation polish alone.

## Value test

For every lesson ask:

> **What can the learner diagnose, design, test or explain after this lesson that they could not do reliably before it?**

If the answer is unclear, the lesson needs stronger teaching, practice or assessment.
