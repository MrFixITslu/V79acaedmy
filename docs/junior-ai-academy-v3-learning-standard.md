# V79 Junior AI Academy — Curriculum v3.1 Learning Standard

## Graduate outcome

A learner who completes the course should be able to use AI **efficiently, safely, critically and independently** on a new task.

Completion is not demonstrated by producing an impressive AI output. A graduate should be able to explain and demonstrate the process:

**DEFINE → CHOOSE → PROMPT → CHECK → IMPROVE → SAVE**

### 1. DEFINE
The learner can:
- state the real result needed;
- separate a large task into smaller jobs;
- identify what “good enough” means before generating;
- distinguish the learning goal from the production goal.

### 2. CHOOSE
The learner can:
- decide whether AI is appropriate;
- choose between AI, search, calculator/spreadsheet, design tool or human judgment;
- choose the AI operation needed: **generate, summarize, extract, transform, compare, explain, critique or plan**;
- consider checking cost as part of efficiency.

### 3. PROMPT
The learner can:
- state a specific task;
- provide only relevant context;
- set constraints;
- identify audience;
- request a useful output format;
- use an example when necessary;
- use source material without allowing unsupported additions;
- write a focused follow-up instead of repeatedly starting over.

### 4. MANAGE CONTEXT
The learner can:
- continue a conversation when previous context is still useful;
- compress a long conversation into a clean approved brief;
- start a new conversation when old instructions are causing confusion;
- avoid carrying unnecessary private information into new prompts.

### 5. CHECK
The learner can:
- check whether instructions were followed;
- verify important factual claims using appropriate sources;
- separate claim from evidence;
- identify uncertainty and missing evidence;
- check privacy, permission and misleading implications;
- use explicit quality criteria rather than “does this look good?”

### 6. IMPROVE
The learner can:
- identify the highest-impact weakness;
- change one weak part while preserving good parts;
- reject poor AI suggestions;
- revise with human intent and judgment;
- distinguish a useful iteration from a random retry.

### 7. SAVE & REUSE
The learner can:
- save reusable prompt patterns;
- document when a template should and should not be used;
- save checklists and quality gates;
- save multi-step workflows with clean handoffs;
- adapt reusable patterns to a new audience or task instead of copying blindly.

## Every lesson must earn its place

Each of the 48 lessons must deliver measurable learner value.

### Discover lessons must include
- a mental model explaining why the skill works;
- operator moves;
- real-world use;
- when AI is and is not appropriate;
- a weak-versus-strong worked example;
- coach questions and reflection.

### Create lessons must include
- a repeatable skill recipe;
- reusable prompt/workflow pattern;
- guided practice;
- micro-drills;
- common failure patterns and fixes;
- focused follow-up practice;
- structured-output practice where relevant;
- an independent operator task;
- explicit evidence of mastery;
- an efficiency metric;
- transfer to a different task.

### Studio lessons must include
- application to the long-running project;
- measurable mastery targets;
- an efficiency target;
- process evidence, not just polished output;
- human/AI/tool role decisions;
- checking and quality criteria;
- an item added to the Team AI Playbook;
- individual exit-ticket explanation.

## Mission 16 — AI Operator Benchmark

Mission 16 includes an individual benchmark using a task that was **not** used as a class example.

The learner must independently demonstrate:
1. DEFINE the result.
2. CHOOSE the operation/tool.
3. PROMPT with context, constraints and format.
4. CHECK instructions, quality, evidence, privacy and uncertainty.
5. IMPROVE the weak part with a focused follow-up.
6. SAVE one reusable pattern.
7. EXPLAIN what AI did, what the human decided and when AI would not be appropriate.

A polished output alone does not pass.

### Graduation rubric

Use the printable **AI Operator Graduation Rubric** during final review. Score six areas from 1–4:

1. **DEFINE + CHOOSE**
2. **PROMPT + CONTEXT**
3. **CHECK + VERIFY**
4. **IMPROVE**
5. **SAVE + TRANSFER**
6. **EXPLAIN + RESPONSIBILITY**

Recommended pass standard: **no category below 3 (Competent)**. If a category is still Developing, return **Needs Changes** with one clear next action and allow the learner to demonstrate the skill again.

For new Mission 16 approvals, every learner on the team must submit:
- the benchmark task/tool-choice description;
- process evidence;
- their own explanation.

The instructor interface displays this evidence, and Mission 16 cannot be newly approved until all three learners submit it.

## Red-team failure conditions

The course should be considered weakened if future edits do any of the following:
- reduce lessons to definitions plus an activity;
- reward prompt length instead of prompt relevance;
- teach brand-specific button clicking as the main skill;
- make AI the default tool for every task;
- present AI output as evidence;
- remove independent verification;
- teach random regeneration instead of focused iteration;
- measure only final-output polish;
- remove transfer to new tasks;
- allow Mission 16 approval without individual benchmark evidence.

## Value test

For every lesson, an instructor should be able to answer:

> **What can the learner do after this lesson that they could not do reliably before it?**

If the answer is unclear, the lesson needs more teaching, practice or assessment.
