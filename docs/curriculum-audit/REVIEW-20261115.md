## Monthly membership: blocked by live provider configuration

Read-only inspection of Hub's production process confirmed: enabled WiPay integration, **sandbox**, country **TT**, currency **TTD**, with existing checkout credentials present and no WAPI key configured. The command completed with exit code 0. No credential values were printed. Academy's current server correctly refuses recurring checkout and never grants paid course access from sandbox transactions.

The Hub internal order API accepts Academy `kind: course` one-off orders. It has no membership order, card-consent, renewal scheduler, failed-renewal recovery or subscription cancellation contract. Its configured sandbox currency cannot establish live USD or XCD settlement support.

WiPay's current [WAPI documentation](https://docs.wipayfinancial.com/wapi) describes trusted cards. [Charge Trusted Card](https://docs.wipayfinancial.com/wapi/trusted-cards/chargeTrustedCard) returns a hosted checkout URL; that alone does not establish unattended merchant-initiated monthly charging. [Transaction metadata](https://docs.wipayfinancial.com/wapi/transactions/getTransactionMeta) is the documented source for supported currencies and limits; its example is not evidence of this merchant's XCD support. [Card creation](https://docs.wipayfinancial.com/wapi/trusted-cards/createTrustedCard) can make a small verification debit, so it was not invoked during this review.

Required before activating the approved **US$35 or EC$94/month** offer:

1. A verified live merchant account and confirmed permitted settlement/charge currency for V79. Confirm both currencies individually; do not relabel a TTD amount.
2. Provider confirmation of the supported recurring flow, consent, authentication/3DS, subsequent charges, refunds/chargebacks and cancellation semantics; securely provision the required credentials.
3. A reviewed cross-app membership-order/entitlement contract, unique transaction and renewal identifiers, calendar-month calculation, replay prevention, recovery after timeouts, failed-payment rules and reconciliation.
4. Opt-out stops future renewals while retaining access until the authoritative paid-through timestamp. Academy's existing non-renewal preference is not a provider cancellation.
5. Sandbox full-flow validation followed by an explicitly scoped live payment acceptance test. No real payment or card-enrolment request was made here.

Do not change existing one-off billing, assume that all current free programmes are now paid, or display fabricated subscription activity.
